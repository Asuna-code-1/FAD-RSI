二、方法与论文结果
问题：长响应中的学生前缀偏离教师分布后，后续 token 监督越来越不可靠，更新可能加剧错误轨迹、长度膨胀和梯度尖峰。只裁剪损失不能修复前缀。
ATI-OPD 先生成完整学生响应，再以固定 128-token 段监测师生分歧。使用有数值裁剪的 sampled-token K3 分数，找到平均分数首次超过 0.15 的段。
教师替换该处最多 128 个 token，学生从修改后的前缀继续生成。主设置每条轨迹只干预一次，保留学生和教师 token 的 OPD 监督。
对新的学生后缀，以 64-token 窗口检查分歧；两个连续有效窗口超过阈值时，屏蔽这两个窗口及后续 token 的蒸馏损失。阈值来自原始正确响应窗口均值的滚动池（2048 项）的延迟 90% 分位数，至少积累 128 个窗口才使用；此前为 0.15。
后缀在决定损失掩码前已完整生成，所以屏蔽监督不是节省这些 token 的生成成本。
教师是固定 RL 模型，测试只使用学生。它属于教师干预的 on-policy 蒸馏稳定化，不是教师／改进算法自身共同进化的完整 RSI。

论文表 1 的五任务等权平均：DeepSeek 学生 OPD 38.45%，ATI-OPD 39.65%（+1.20 个百分点）；Nemotron 学生 OPD 52.72%，ATI-OPD 54.07%（+1.35 个百分点）。这些是论文报告值，不是本地测得值。
每题生成 16 条响应后平均正确率。表中误差主要反映推理采样，并不等同多次独立训练的稳定性；部分敏感性实验只有一次训练。
主参数：217 步，batch 64，每题 rollout 4，AdamW lr=1e-6 常数，weight_decay=0.01，grad_clip=1；prompt 上限 1024、response 上限 23552；训练采样 temperature/top_p=1；评测 temperature=0.7、top_p=0.95；student top-k=16 的精确教师评分路径。

四、环境与本地修改
Python 3.12.3，Torch 2.10.0+cu128，vLLM 0.18.0，Transformers 4.57.6，HF Hub 0.36.2，NumPy 2.2.6，FlashAttention 2.8.3，自带 verl 0.8.0.dev。
ATI 仓库没有给出可直接用于本机的完整 GPU 锁定环境；本地配置是经过导入、CPU 算法测试与 GPU 注意力验证的兼容实现，实际版本锁定在 environment-freeze.txt。
verl setup.py 的旧 NumPy<2 限制与新 vLLM/OpenCV 依赖冲突，元数据调整为 >=1.26,<3。
修复 logprobs_from_logits 在 CPU 张量上误调用 FlashAttention CUDA 交叉熵的问题：仅增加 logits.is_cuda 判断，CUDA 训练路径不变。该问题在原生 CPU 测试中实际复现，修改后 101 项相关测试全部通过。
runtime.patch 保留全部源码变更；没有修改干预阈值、窗口校准或损失算法。
